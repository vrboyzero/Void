# 灵榜跨电脑接入

接收端运行 DSH + 灵榜，发起端只需 MCP Client（客户端）。每台目标保留自己的工作区、会话与账本。家里、公司、店里使用不同连接别名和独立 token。

## 本机准备

- 仓库根运行 `pwsh -File scripts/pack-lingbang.ps1 -SkipInstall`。白名单编辑器还需构建、安装更新后的 `@void/void-entry`。
- 升级前备份 profile 的 package.json 与 cordis.patch.yml，按 `remove → 残留包目录移到回收站 → add 新 tarball` 更新并核对文件内容，保留用户已有配置。
- WebServer 保持 loopback 监听，例如 `127.0.0.1:3080`。灵榜 `allowAnonymous=false`、`allowedOrigins=[]`；原生客户端不发 Origin，无需把 Serve 地址加入此列表。
- 调用方表格每个远程身份独立配置 tokenEnv、operations、workspaceIds。workspaceIds 空列表拒绝全部工作区/会话，`["*"]` 显式授权全部。在启用 Serve 前，可通过可信本机管理 token 的 `dsh_list_workspaces` 取得 ID，再把所需 ID 分给远程身份。
- 初期只给 workspace.read、session.list、session.prompt、task.read；新建 Workspace、原生计划、steer/inject、取消分别决定。受限调用方只能按路径解析已有获准 Workspace。

token 使用至少 32 字节加密随机值。PowerShell 7：`$lingbangPairToken = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))`，赋值不会输出变量。通过可信秘密存储交给双方，变量名可以不同。不要把值放进参数、URL、普通配置、Session 或提示词；修改 `.env` 后重启对应进程。脚本不会写 `.env`。

**升级影响**：旧 token 未配置 workspaceIds 时也解析为空列表。旧账本中没有 Workspace ID 的直接消息任务，仅全工作区可信 token 可查询；撤权后旧 MCP Session 的下一次调用同样受限。

## 预览、启用与回滚

```powershell
# 只预览本机地址、Serve 命令、Codex/DSH 客户端配置
pwsh -File scripts/lingbang-remote.ps1 -ServerName office-dsh -TokenEnv LINGBANG_OFFICE_TOKEN
# 预览启用流程；实际写入需显式加 -Apply
pwsh -File scripts/lingbang-remote.ps1 -Action Enable -TokenEnv LINGBANG_OFFICE_TOKEN
# 预览回滚；实际撤销需显式加 -Apply，参数与启用时一致
pwsh -File scripts/lingbang-remote.ps1 -Action Disable
```

`-DshPort` 指定本机端口，`-HttpsPort` 默认 443，`-McpPath` 默认 /mcp/dsh-agent-control，`-TokenEnv` 是变量名。脚本检查 Tailscale 在线和 MagicDNS。启用前验证匿名 401、陌生 Origin 403、指定凭据通过鉴权；快照存入 `.tmp/lingbang-remote/`。已有 Serve 配置时拒绝覆盖，需先检查并人工合并；不改 ACL、不启用 Funnel、不安装软件。

确认所在网络允许该用法，在 tailnet grants/ACL 中只允许指定发起端访问目标 tcp:443。ACL 不区分 URL 路径，Serve 只挂 MCP 路径。代理目标必须包含同一完整路径：

```text
tailscale serve --bg --https=443 --set-path=/mcp/dsh-agent-control http://127.0.0.1:3080/mcp/dsh-agent-control
```

Serve 先剥掉挂载前缀再拼目标路径；只写目标端口会把精确 MCP 请求转成 `/`。已核对本机 1.104.2 同版源码 serveWebHandler/reverseProxy.ServeHTTP，仍需外机实测。回滚只移除匹配本次参数的单路径代理，不用 serve reset；失败时检查 serve status 后按打印命令关闭。

## 客户端与现场验收

Codex 使用生成的 `[mcp_servers.office-dsh]`、bearer_token_env_var 和 `default_tools_approval_mode="prompt"`。DSH 使用独立 serverName 和 `headers: !!js` 环境表达式；支持状态以方案 §30 的真机证据为准。发起端凭据来自自己的启动环境，不能假定 Codex 读取 DSH 的 `.env`。

2026-10-24 实测：Codex 0.164.0 协商 MCP 2025-06-18，DSH 0.2.1-rc.2 协商 2025-11-25，均可发现并调用工具。**DSH 在协议 Session 被回收后不会自动重新握手**：调用失败时重载那一个 MCP 插件入口，再按原 taskId/afterCursor 继续查询，重试派发仍沿用原 requestId。Codex 的失效 Session 自动恢复已在隔离环境通过；实际网络断线仍需现场验证。

```powershell
# 只读诊断；先安装仓库独立灵榜包的依赖
node scripts/lingbang-remote-smoke.mjs --url https://TARGET.TAILNET.ts.net/mcp/dsh-agent-control --token-env LINGBANG_OFFICE_TOKEN
```

诊断覆盖认证、Origin、两次握手、工具发现、范围，不派发任务、不输出 token/header/正文。失败非零退出，不当作送达。可加 `--task-id ID --after-cursor CURSOR` 续读已有任务。

- 从另一台获准设备确认 MCP 可用，而 `/`、`/api`、`/api/settings/describe` 不出现 DSH Web UI/API。
- 在真实设置面板为指定调用方输入 Workspace ID 后立即点保存；刷新后白名单仍在，获准工作区可查询。清空保存后，既有 MCP 连接下一次工作区/任务访问被拒绝。此 UI 手测尚未执行。
- dsh_control_info 返回当前权限与 workspaceScope；枚举只含获准项目；越权 Workspace/Session、文档引用与任务查询被拒绝。
- 发送前固定 requestId；超时/重连沿用同一 ID，应返回同一 taskId。用 dsh_get_task/dsh_wait_task + afterCursor 续读，不能新造 ID 盲目重发。
- 原生计划仍在目标 Web 人工评审；长任务采用接受即返回和短时轮询。撤销 token 后，旧 MCP Session 下一次请求也失败。
- home-dsh、shop-dsh 分别指向不同目标；一台离线不影响另一台。任务按 `(连接别名, taskId)`、Session 按 `(连接别名, sessionId)` 跟踪；路径和文档在目标端解析。

Cloudflare 仅在公司策略不能用 Tailscale 时另行验证。依据：[Serve CLI](https://tailscale.com/docs/reference/tailscale-cli/serve)、[同版路径重写源码](https://github.com/tailscale/tailscale/blob/v1.104.2/ipn/ipnlocal/serve.go)、[Codex MCP](https://developers.openai.com/codex/mcp/)。进度和实测证据见方案文档 §30。
